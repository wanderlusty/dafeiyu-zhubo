# DeepSeek「DS 主播」调研与本地试播路线

更新：2026-11-03。目标：一只持续存在的 DS，先在 Windows 电脑本地试播；以后用独立的普通 QQ 小号聊天，用独立 B 站账号看视频、运营评论、投稿，并在直播间读弹幕、语音回应。网页探索也归同一角色的经历。

**当前组合：**以 `dsh-world@0.7.0` 作为 DS 的身份与未来普通 QQ 通道（SnowLuma/OneBot），以 `dsh-bili-scroll@2.4.0` 做只读 B 站日报，以 `bili-agent@1.2.1` 做可预览的投稿和账号操作。三者已经在隔离环境安装或加载；B 站插件已登录并完成一轮只读浏览，使用 OpenCode Go 的 DeepSeek V4.1 Flash 生成日报。`dsh-world` 的角色世界尚未启动，也未接 QQ；刷 B 站值班轮仍是独立 profile，**目前只有一致的人设，没有自动共享同一段会话与记忆**。接下来要对日报做来源标注和去重，再送入长期记忆。`dsh-livestream` 用于后续 OBS 本地彩排；Coopanion 可作视觉舞台候选，但若使用其独立角色宿主会带来第二套记忆。Aurabot 不与这套组合同时接管同一 QQ/B 站账号。

## 本机现状与顺序

Windows 上有 Node 24、Python、uv、RTX 4060 8GB，以及 `~/.dsh` 的 desktop/web/headless profile；全局 `dsh --version` 是 **0.1.1-rc.2**。本项目另建 `D:\PRJ\ds-zhubo\.dsh-home`，使用 DSH **0.2.1-rc.5**，未改 `~/.dsh`。已装两个插件和 `bili-cli`；在网页 127.0.0.1:3081 验证世界控制台和“刷 B 站”接口加载，B 站登录自检已全部通过。OpenCode Go 模型已完成最小请求和一轮只读浏览，详见 `本地搭建记录.md`。当前未找到 `ffmpeg` 命令或 OBS；没有发送任何公开消息。

1. 核对实际运行的 DSH 路径与版本，备份现有 profile；选一条 QQ/记忆主路线，不把多套 QQ 桥和多套记忆同时装上。
2. 创建角色设定和只读生活日志；在本机模拟 QQ 消息、B 站评论与直播弹幕，确认她的回答和记忆一致。
3. 用普通 QQ 小号接 OneBot，只允许你的 QQ 号私聊，接口仅绑定本机并设置 token；先测试收/回消息，再测试主动联系。普通账号自动化依赖非官方协议，可能遇到封控。
4. B 站小号先只读浏览和生成评论草稿；开放互动时优先自己的视频评论区与别人明确 @ 她的回复，设去重、每日上限和停用开关。不要对每条看过的视频自动留言。
5. 安装 OBS 与语音组件，在 `dsh-livestream` 本地彩排里测试读弹幕、语音、人物画面和断线恢复；通过后再使用 B 站开播资格。
6. 先做原创素材的视频草稿、成片和本地预览，核对画面、声音、版权与 AI 标识，再进入投稿步骤。

注意：`dsh-onebot-qq` 这个名字在 npm 上当前指向 [mario841859784/dsh-onebot](https://github.com/mario841859784/dsh-onebot)，而 [YUsaltyfish/dsh-onebot-qq](https://github.com/YUsaltyfish/dsh-onebot-qq) 是另一仓库，后者声明需要 DSH `>=0.2.1-rc.2`。安装时应固定仓库地址、版本和使用的 profile，不能只抄视频里的包名。B 站明确要求 AI 生成内容标识，也禁止自动刷评；“鱼灾”视频值得作为互动节制的提醒，但具体设置应以平台公告及项目源码为准。
