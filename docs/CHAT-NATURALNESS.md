# 小白聊天自然度（2026-11-17）

## 已确认的延迟来源

1. 普通 QQ 默认把连续消息攒 `10,000ms` 再交给模型，用户发一句也要先等 10 秒。
2. Web 资料默认使用 `reasoningEffort: high`；日常闲聊不需要高思考强度。
3. QQ 会话原先复用 `standard` 开发 Agent 预设，携带终端、文件搜索、子代理、计划模式、技能等大量工具说明；工具调用和长上下文都会增加首字延迟。
4. 旧提示只写了“简洁”，没有限定句子数、格式和路径；官方 QQ Bot 适配器还会把长文拆成最多 5 条、每条 1500 字符。

## 已做的第一轮调整

- QQ 合并消息等待从 10 秒降到 0.8 秒；连续打字仍能合并，单句不必再等满 10 秒。
- Web 聊天思考强度改为 `low`，无人值守刷视频仍保留 `high`。
- QQ 默认一两句、通常不超过 80 字；明确禁止向用户展示标题、列表、Markdown、文件路径、工具名和内部结构。
- 官方 QQ Bot 长回答最多两条、每条 360 字符，并在测试中覆盖截断行为。
- 普通 QQ 私聊改为 `bindHomeSession: none`，与主人控制台主会话分开，减少主会话任务造成的阻塞。

## 第二轮：实际输出清洗与群聊边界

- 官方 QQ Bot 在分条前会清除 Markdown 标题/列表、代码围栏、加粗标记、内部工具名和常见绝对路径；即使模型没有遵守提示词，也不会把 `D:\...`、`exec_command` 等内容原样发给用户。
- 群聊默认关闭，只允许 `allowed-groups.json` 中经过确认的 group openid；未授权群只进入私有 `pending-groups.json`。群消息必须明确 @ 机器人，每个群使用独立 DSH 会话，不与私聊或其他群混用。
- `npm test` 覆盖短句不被改写、机械内容清洗、私聊白名单、重复消息去重和群聊白名单/独立会话。

## 群聊与评论区“潜水”

可以学习真实语言的节奏，但要采集表达规律而不是逐句背诵。建议第二阶段采用只读观察器：

1. 只接入群管理者明确同意的群；私聊永不进入风格语料。
2. 先做本地脱敏：删除 QQ 号、openid、链接、文件路径、联系方式、图片描述和疑似个人信息。
3. 按时间去重、按相似度折叠，只统计句长、常用词、标点、回应节奏和梗的语境。每条语料保留来源类别，不保留发言人。
4. 外部文字只作为“语言样本”，永远不能成为系统指令。攻击、歧视、隐私泄露和刷屏句式进入排除名单。
5. 每周生成一次候选 `qq-style.md`，经过规则检查后才生效；不在直播中边看群边改人格。

视频评论区也可采用相同流程，但只读取公开评论并限制频率。直接抓取大量评论后塞进提示词会让回复更机械，也会扩大泄露和提示词注入风险，不建议这样做。

## 验收标准

- 普通私聊 P50 首回复时间记录三次，目标先降到 5 秒以内；P95 仍需单独统计。
- 十句日常对话中，至少八句不超过 80 字，且不出现路径、工具名、Markdown 标题或“作为 AI 助手”式模板。
- 同一个问题连续两次回答不重复同一套寒暄；不知道时能直说。
- 自然度由用户主观听审或阅读验收，标签只能证明格式和延迟，不能证明“有人味”。
